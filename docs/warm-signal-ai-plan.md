# 心动来信 · 大语言模型聊天策划与接入验收

日期：2026-10-09。玩家在「设置 → 服务地址与模型设置」或「在你身边 → 聊天 → 右上角菜单 → 连接设置」配置自己的服务。六位女生分别保存对话，使用原创人设及当前男主姓名、好感构造上下文；模型回复不会修改金币、好感或任务结果。

## 连接与消息

采用 OpenAI 兼容的 POST /chat/completions。填写根地址时补 /v1，填写 /v1 时补 /chat/completions，也接受完整接口地址；仅支持 HTTP/HTTPS，不把密钥放进 URL。模型名称由玩家填写，不锁定供应商。温度留空时不传入该参数，上下文可设 1～20 轮，默认 10 轮。

支持 JSON 非流式和 SSE 流式回复；正确处理 UTF-8 分片、CRLF、心跳与结束标记。90 秒超时或玩家停止时取消请求，不自动重试；不完整流、错误和取消均不写入历史。失败保留输入供玩家重发。返回文字使用 textContent 展示。

连接测试只发送一条短测试消息，不带游戏聊天历史。服务需允许网页跨域访问；部署到 HTTPS 后使用 HTTP 本地接口还受浏览器网络规则限制。此次实际测试的是 localhost 页面到用户指定 HTTPS 服务。

## 多模态

玩家主动选 PNG/JPEG/WebP，单张不超过 4 MB；选择后先显示预览，点击发送才将 data URL 作为 image_url 与文字一同发送。图片不保存在对话历史；历史仅记录文字、[附图] 标记与回复。导出游戏存档不包含 AI 配置、聊天历史或附图。

当前实现的是「文字＋图片输入、文字输出」。语音输入、视频输入、生成图像、模型语音输出尚未接入；可选朗读使用设备 TTS，并驱动人物临时嘴部动作。

## 本地保存

服务地址、模型、生成参数存本机浏览器。API Key 默认仅保存在本次页面内存，刷新需要重新填写；玩家明确勾选「在此设备记住 API Key」后才写入浏览器。提供忘记密钥按钮。这里没有独立服务端密钥托管或加密保险库。

六个角色各保留最近 20 轮成功对话；切换女生保持隔离，刷新恢复。清空对话需要明确确认；停止请求不会删除已有对话。原游戏存档与 AI 配置/记录使用不同存储键。

## 手机 QQ 式聊天布局（2026-10-09）

按用户反馈，将 AI 表单弹窗改为占满竖屏游戏区域的聊天界面。手机中新增「AI聊天」角色列表入口；原有短信剧情继续单独使用。入口仍在 WarmSignal.html，无需跳转外站。

- 顶部固定返回、居中角色姓名和「AI 陪伴 / 正在输入…」、右侧更多菜单。
- 中间只滚动聊天记录，女生在左、男主在右，双方都有头像；奶油白与暖粉气泡，暖米色背景，豆沙色发送按钮和玩家头像，文字统一为暖棕色。
- 底部固定图片、自动增高文字框、表情和发送。附图缩略图可移除，表情面板展开时压缩消息区域，不覆盖输入栏。
- 连接设置、新对话和说明放入右上角菜单。新对话仍需确认后才清除该角色历史。生成中提供停止按钮，失败/取消恢复草稿，不写成功历史。
- 每位角色的草稿与本次附图保存在当前页面内存，菜单/设置返回后恢复；刷新不保留未发送草稿。聊天历史仍分别保存最近 20 轮成功文字。
- 回复过程中，仅在玩家接近列表底部时跟随滚动；保留 Enter 发送、Shift+Enter 换行，中文输入法候选确认不会误发。消息按纯文本输出。

布局参考手机 QQ 的顶部导航、双边头像气泡与固定输入栏结构，参考入口为[手机 QQ 产品页](https://im.qq.com/mobileqq/)。按钮、配色及图标由本项目实现，没有使用 QQ 标志或素材。

实际浏览器验收：当前面板真实视口 465×655，文档宽 465；顶部 0～74、消息列表 74～599、输入栏 599～655，没有覆盖与横向溢出。设置返回保留草稿，表情成功插入；选取本项目原创 companion-scenes-v1.jpg 后显示缩略图和文件名，移除正常。实际发送返回连接错误，原文字恢复；再次发送立即停止后显示「已停止，消息未保存」，返回并重进仍只有原先两轮成功对话。最终刷新后配置及历史保留、输入为空，页面 error/warn 日志为空。
