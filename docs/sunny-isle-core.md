# 晴岛夺核：内核、受众与实现

内核：战斗中改变敌人系统的归属与连通性，让“摧毁”和“保留反用”形成实际取舍。低频操作通过持久策略延续；成长解锁更复杂的系统，不把挂机等同于没有决策。

受众：愿意理解少量系统规则、喜欢自动交战反馈、经常同时看电视或视频的玩家。解压来自威胁逐渐停机、反用生效、碎裂反馈与稳定积累；目前是设计目标，不能声称已有玩家研究证明治疗或减压效果。

## 引擎

独立入口tools/SunnyIsle.html，目录tools/sunny-isle。与旧游戏及种植草稿分离，主线48关、试炼6关、守望者3名、研究12项、器具8种、成就16项、剧情12段均由数据驱动。

纯逻辑UMD引擎可在浏览器和Node加载。固定0.25秒逻辑步；供能按源节点与有向路径分配，结构变化时重算。每次攻击、治疗、接管与覆写都由同一引擎执行；在线、离线与测试不采用不同奖励公式。

存档采用版本和输入校验，保留进度、已解锁内容、资源、研究、装备、持久策略、当前战斗节点及定时器、统计、设置与时间戳。导入先校验，失败不覆盖现有存档。重置需产品内确认。导出可下载JSON，不依赖账号、网络付费或外部服务。

离线最多24小时，前台逐块推进并显示补算进度，结束给出真实战斗次数、失败与资源差额。暂停不补算；倍率改变不能追溯改变上段离线时长。页面隐藏时保存，回到页面补算，避免同时在线推进和补算重复计时。

## 验证要求

检查供能路径、能源分配、接管归属、容量释放、覆写和伤害因果；策略对照不得偷偷修改伤害倍率。验证48关可到达、不同结构有策略取舍、固定规则试炼有合理解法；研究是否有实际作用；序列化连续性与离线等价；导入损坏/未知版本/越界数值；实际手机尺寸界面、触控、存档、导航、剧情图片与控制按钮。

算法与内容检查只能证明规则成立，不能证明好玩。需在浏览器观察真实战斗、策略调整和完整功能，再继续迭代。工具页仅在可玩入口运行并验证后加入，不能提前把策划规模写成已实现。
