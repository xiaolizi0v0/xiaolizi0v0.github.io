## 玩家流程

首页左侧「我的好友」、制作人资料页「我的好友」、邮箱「好友邮件」均可进入。

1. 初次填写好友服务地址、选择头像，点击连接；显示8位玩家ID。服务保存名字、等级、羁绊收集数量和头像编号，供同一服务的其他玩家查找。
2. 「结识好友」按完整ID或完整名字查询，也可随机查看最多20位推荐制作人。申请发出后显示已申请；对方接受才建立双方关系。重复/交叉申请和满员均处理，不自动接受。
3. 「好友」显示99人上限、头像、制作人等级、羁绊数、最近访问时间；可逐个赠送或一键赠送。每对好友每个服务日可赠送一次，赠送不扣发送者体力。已赠送、暂停接收分别展示；删除后重加不会重置当日赠送。
4. 「申请」显示申请人资料，接受/拒绝；申请7天到期。删除好友需页面二次确认，双方列表同步解除；原已收到的邮件保留。
5. 「好友邮件」显示赠送者、体力3、到期小时数、今日已领0～20；逐条或一键领取。超过制作人自然回复上限仍可收取，资源硬上限100万时保留回执待消耗后补发。
6. 「接收好友体力」关闭后不接受新赠送，已有邮件仍可领取。5点刷新的是赠送/领取额度；已赠送邮件按72小时独立过期。
7. 页面刷新会重新同步身份与资料，不重建账号、不改变头像、不重复发体力。连接失效会显示错误并提供刷新；保留已有列表直到下一次同步成功。

好友列表按服务最后访问排序，时间来自最近一次服务快照。没有自动在线心跳，不把「刚刚来过」标为持续在线。界面内部滚动，底部赠送/领取固定在内容之外；320×568已验证没有水平溢出或底栏压住内容。

## 服务及存档

实现为Python标准库HTTP服务及SQLite，无需安装第三方库；浏览器游戏仍是原生静态页面。独立服务不占用或读取玩家的大模型地址、API Key、聊天图片、聊天历史和模拟付款数字。

在仓库根目录启动：

```powershell
python tools/warm-signal/friends-server.py
```

默认监听 `127.0.0.1:8766`，游戏地址仍为 `http://127.0.0.1:8765/tools/WarmSignal.html`。默认允许该127.0.0.1及localhost的8765页面来源，不配置通配CORS；不自动开公网或局域网端口。数据库默认位于 `%LOCALAPPDATA%/WarmSignal/friends.sqlite3`，代码禁止主程序把数据库放进本静态网站目录。

`--port`、`--db`、`--origin`可改变端口、库路径和允许来源；`--origin`可重复传入。远程玩家需要同一HTTPS反向代理服务和对应网页来源配置，不能把各自的127.0.0.1当成同一个服务。当前只验证本机HTTP联调，没有部署公共服务器。更换服务地址或数据库身份时，不自动覆盖已有浏览器身份。

服务生成8位随机ID和随机Bearer凭据，库中只存凭据SHA-256摘要。浏览器连接身份保存在独立键 `warm-signal-friends-connection-v1`，不混入游戏导出；页面不显示凭据。没有密码输入、真实支付或第三方登录。当前没有账号找回、身份导出或迁移页面，清除浏览器数据会丢失该好友身份；备份游戏JSON不能恢复身份。

游戏新子存档为：

```text
friends = {version: 1, credits: {"服务随机标识-玩家ID": 已入档累计体力}}
```

最多记录64个历史身份；旧游戏存档迁移为空账本，保留原有资源、卡牌及全部玩法。导入验证版本、账本结构、身份键、整数边界及3点倍数。

服务领取在单次SQLite写事务中完成：校验身份/邮件所有者/到期/日上限，标记邮件并增加该账号累计已领取体力。赠送使用发送者、收件者、服务日的唯一约束；双方关系的建立/移除也在事务内完成。服务记录最大已见时间，时钟回拨不恢复旧额度。连接使用提交/回滚上下文并显式关闭，参见[Python sqlite3官方文档](https://docs.python.org/3/library/sqlite3.html#how-to-use-the-connection-context-manager)。

客户端同步服务累计值，只增加累计值与本地账本的差额；资源与账本同步保存，保存失败恢复本轮内存状态，回执仍在服务端。网络在服务领取后断开时，后续 `/state`可补发差额。已有本地累计值高于服务时拒绝回退，避免恢复旧服务数据库后再次发放。支持Web Locks的浏览器对好友入档串行化，发现其他页面已改变回执时要求刷新。

游戏整体仍使用本地JSON钱包，不能视为服务端权威经济或防修改存档系统。原有多标签自动存档不具备整体事务合并，应保持一个活动游戏页面；好友回执检查不能保证所有玩法并发存档都无覆盖。此限制不以单元测试代替说明。

## 接口

| 接口 | 用途 |
| --- | --- |
| GET /health | 协议版本和服务身份 |
| POST /register | 建立本地设备好友身份 |
| GET /state | 列表、申请、邮件、额度、累计体力回执 |
| POST /profile | 同步名字、等级、卡牌数量和头像编号 |
| POST /search、/recommend | 完整ID/名字查找、最多20位随机推荐 |
| POST /request、/respond、/remove | 申请、接受/拒绝、双向移除 |
| POST /gift | 指定好友或all赠送 |
| POST /receive | 开关新赠送接收 |
| POST /claim | 指定邮件或all领取 |

除健康检查及注册外均需Bearer身份，写接口要求JSON且最多16KB，不使用Cookie。查询只返回公开资料，不返回其他玩家凭据。SQL使用绑定参数，HTTP不输出请求体、令牌或玩家名字日志。服务默认最多10000身份；本版本没有运营级注册限流、封禁审核、账号恢复、托管TLS、监控或公网负载验证，公网正式运营前仍需完成这些工作。
