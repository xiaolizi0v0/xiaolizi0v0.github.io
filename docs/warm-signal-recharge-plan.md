玩家从顶部钻石加号或「拾光小铺」进入充值页，完成「选择档位 → 确认订单及支付方式 → 输入任意4位数字 → 确认模拟支付 → 成功到账」的完整流程。全部为本地游戏数据，不接入真实收款、支付SDK或外部钱包，不设置真实付款密码。

参考[恋与制作人官方2026年6月30日公告](https://evol.papegames.cn/news/892)中的各档位首次购买双倍及累计充值回馈结构。官方公告中的限期活动和限定角色奖励不直接搬用；本项目采用六位原创女生与常驻演示奖励。

研究中发现的[生日商城截图所在攻略](https://www.qieyou.com/content/151314)可作为后续商城分类参考，但该截图原图请求超时，本轮没有据此声称逐像素还原。实际支付面板随原作渠道、系统和支付平台变化，本轮实现统一的本地模拟面板；4位数字是用户明确指定的规则。六档数值、常规赠送和首充礼均为本项目模拟表，尚未完成原作各平台充值界面的逐项核对。

## 页面与交互

- 充值页采用奶油底色、豆沙玫瑰按钮、浅杏金边、原创SVG切面钻石。顶部显示余额和充值记录，中间三列两行商品，下面是SR自选首充礼与累充回馈。
- 确认页显示模拟金额、基础钻石、赠送钻石、订单号，并可选「模拟余额 / 模拟微信 / 模拟支付宝」。三种方式只影响订单展示，均在本地完成。
- 支付页支持键盘输入和屏幕数字键盘、删除与清空，遮蔽输入数字。不足4位时按钮禁用；仅接受ASCII数字0～9，四位数字无需预设或注册。确认后立即显示实际发放的基础和赠送数量。
- 返回订单可重新选择支付方式；「取消订单」结束订单，不发钻石、不增加累计金额，也不占用首充。关闭弹窗暂存订单，充值页显示继续与取消；刷新恢复订单阶段，但清空已输入的数字。
- 成功后可完成、查看记录，或领取尚未领取的首充礼。已领取首充礼时展示当时选择的女生并禁用选择，避免误以为可以重新领取。
- 320×568支付页全部12个键与底部动作可同时显示；更短屏幕允许内容内部滚动，底部确认操作保持可见。

## 存档与交易规则

新增 `recharge` 子存档，包含版本、单调订单序号、六档成功购买次数、累计模拟金额、首充礼选择、已领取回馈、待支付订单及最近50笔终态记录。旧存档首次载入时建立空充值记录，保留原有钻石、金币、卡牌和所有玩法进度。

订单有确认、支付、已支付、已取消四种状态。确认与支付操作核对订单号和阶段；一个待支付订单完成或取消后才能建立下一个。成功发钻、累计金额、次数、回执及清除待支付订单在同一次同步事务完成；重复点击或旧订单号不再次发奖。充值历史超出50条时只截断展示记录，累计金额与首充次数继续保留。导入校验金额与购买次数、商品、订单序号、阶段、回执奖励、领取资格和数值边界。

模拟数字只存在临时界面内存，不写入订单、存档、历史记录、日志或外部请求；返回、关闭、成功后清空输入。导出存档包含模拟充值进度，不包含模拟数字。它仍是可导出编辑的单机存档，不具备真实支付服务的账户或签名验证。
