# 战斗机制创新审查

2026-10-08。当前研究记录，不是获认可的正式玩法或已完成游戏。用户不需要自行提供主要玩法，由开发者负责调研与创新。上一版五人编队、三种战斗爽感提议均已被否定。

## 已知机制与证据

|机制|已有作品的直接证据|本项目不可声称|
|---|---|---|
|布置单位后自动战斗|[TABS官方](https://landfall.se/tabs-press-kit)的物理战斗模拟；[Gladiator Guild Manager商店](https://store.steampowered.com/app/1043260/Gladiator_Guild_Manager/)介绍站位和行为指令后自动交战|布置本身是新玩法|
|条件行为自动执行|[Gladiabots官方](https://gladiabots.com/)介绍构建AI并让策略自动运行|给AI加条件就是首创|
|物理碰撞与破坏|[Besiege开发商](https://www.spiderlinggames.com/)介绍物理构建与破坏；TABS也使用物理交战|碰撞、弹开、破坏本身是新玩法|
|利用敌方行动进行战术反制|[Into the Breach开发商](https://subsetgames.com/itb.html)介绍预告攻击和逐回合反制；该游戏的回合/随机挑战不采用为本项目核心|看懂敌人并反制就是新玩法|
|战斗养成与离线奖励|[AFK Arena官方商店](https://play.google.com/store/apps/details?id=com.lilithgame.hgame.gp&hl=en)|挂机养成或更换羁绊名称就是创新|

资料读取边界：Gladiabots和Into the Breach的完整页面部分访问失败，当前结论来自官方搜索摘要；没有据此编造具体算法。其余来自已打开开发商页面或官方商店。截图研究只能支持表现观察，不能替代实际试玩。

## 刚才提议的真实性

“战场布置＋自动物理交战”是现有机制组合，没有证据证明它形成新的主要玩法。把敌人冲击转换为反击也需要继续检索反弹、格挡蓄力类已有设计，不能因为取了新名称就说原创。

可作为一般实施技术的布置，不能独自承担本项目的创新承诺。尚未选定最终方案，不能把当前提议写成用户已经认可。

## 后续筛选标准

1. 明确玩家新增的核心决策，不能只是单位站位、队伍升级或武器换装。
2. 给出同一局面下至少两种结果不同且可解释的决策，并指出已有作品中的近似机制。
3. 新机制改变战斗资源、敌我关系或胜利条件，而非只添加倍率和视觉特效。
4. 自动运行仍可持续，手动决策不依赖几秒内反应，不要求重复布置每一关。
5. 玩家能看懂动作与结果；研究模拟仅验证机制，不声称已证明好玩或解压。
6. 用“对本项目的实质变化”描述创新，未完成充分市场检索和体验验证之前，不声称全球首次。

研究目的是提出和检验机制，不无限堆文档或提前生产大量剧情资产。下一步需把可检验假设落实为内部试验，再形成正式玩法、剧情和内核。
