# 手机屏幕安全区

2026-10-14。`safe-area.css` 统一管理四边避让；游戏内全屏页面使用扣除上下安全区后的高度。主页、全屏玩法、固定弹窗、抽卡演出、聊天均使用同一边界，子页面不重复累加系统内边距。

优先读取 CSS `env(safe-area-inset-*)`。TapTap 发行入口带 `data-platform="taptap"`；移动端且窗口确实覆盖整块屏幕时，为未上报安全区的宿主提供保守留白。已经缩进的 WebView 不添加猜测值。普通桌面浏览器默认零额外留白。

「制作人资料 → 设置与存档 → 屏幕适配」提供自动、挖孔/刘海、大刘海/灵动岛、无额外留白四档，兼容宿主无法上报的设备。该偏好使用独立本机键 `warm-signal-screen-fit-v1`，不读写游戏存档。聊天跟随可视视口调整，键盘出现时不重复预留底部手势区。

已验证：10 项逻辑检查；独立存档的 390 × 844 浏览器预览中，灵动岛档主页 HUD 从 y=59 开始、底栏截止 y=810；许愿树内容和聊天外框为 y=59–810；规则弹窗为 y=79–790。没有测试模拟充值，也没有声称完成 TapTap 真机摄像头/键盘验证。

实现依据：[WebKit 的安全区适配说明](https://webkit.org/blog/7929/designing-websites-for-iphone-x/)。TapTap 小游戏的 `tap.getWindowInfo` 属于另一种运行环境；当前 H5 不假定存在该接口。
