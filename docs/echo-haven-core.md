# 晴岚回响：候选内核与实现设想

状态更新（2026-10-08）：当前不进入本方案产品实现。文中路径与结构是未实施的设计设想；先依据market-gameplay-map.md比较候选机制。

受众：愿意看自动交战、愿意偶尔尝试策略，但经常同时看电视/视频的人。少量操作不等于只有升级按钮；每次留下或修改回声，之后多场战斗自动执行。难度由敌情与空间/时间配合产生，不靠反应考试。解压来自逐渐看懂、调整生效、过去动作形成夹击和安全的长期成长。

产品入口tools/EchoHaven.html；独立目录tools/echo-haven/，不覆写NeonSeasons或旧草稿。UMD数据/引擎供浏览器和Node同用，固定0.1秒逻辑步，在线/离线统一推进。2x作为明确保存的战斗倍率在两边一致执行；暂停期间不补算。补算24小时分块或优化重复已知战斗但必须证明等价，不能直接赋资源模拟通关。

真实记录存40帧片段与每帧攻击对象的空间描述；回声读取片段坐标与真实碰撞范围，不重新决定为命中敌人而瞬移。随身仅做坐标平移并降低倍率；镜像转位置和方向。诱敌回声进入敌方选目标列表，守护职责消耗攻击时点进行治疗。共享能量先扣除再播放，不足时等待，不会因录到大技能无限复制。

状态含版本、战役/训练模式、资源、研究、装备、风格、行为、记录库、三槽配置、方案、完整交战单位和波次、随机种子、滚动记录、离线余秒、一次性故事/奖励。伤害、防御、护盾、破甲、敌人动作、治疗、阵亡由内核统一计算。显示事件有限队列，动画不会改资源。导入按完整结构与合法范围校验，写盘失败可导出备份。

页面五页：战斗（真实场地、血条、波次、回声与指令）、回声（候选剪取、片段轨迹预览、镜像/时机/职责、方案）、成长（等级、装备、18研究）、旅程（72关与六首领）、手账（24故事、战报、图鉴、帮助/设置）。主要按钮44px以上，360px竖屏可使用，无需悬停、鼠标右键或键盘。

完成要求：全部正式玩法内容、生成剧情场景、可读竖屏视觉、持续自动循环、完整存档/离线与辅助设置、自然流程实测和浏览器操作检查。先实现引擎及完整数据，用真实交战验证回声，然后构建UI和素材。当前策划已写，开发目标仍active，不把内部试验当最终游戏。
